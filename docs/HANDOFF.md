# Перед передачей работодателю

Это проверяемый локальный прототип с AI-помощью, а не подтверждение завершённой живой интеграции и не автоматически отправленное тестовое задание.

## 1. Проверить и понять

- Прочитать README и код: почему телефон отличается от MAX chatId; почему успешный POST означает очередь, а не доставку; зачем удалять receipt после обработки; как работает отмена и deduplication
- Самостоятельно выполнить `npm ci`, `npm run check`, браузерные тесты
- Просмотреть демо и исправить/изменить то, что хотите представить как своё решение
- Уточнить у работодателя правила использования AI, если это важно для процесса; не заявлять, что код написан полностью без помощи

## 2. Живая проверка, которую ещё нужно сделать

На отдельном тестовом MAX-инстансе, с собственным ключом и согласным получателем:

1. Настроить HTTP API, выключить другие потребители очереди, сверить apiUrl
2. Ввести ключ самостоятельно локально. Проверить `authorized` и отсутствие ошибок CORS в доверенном браузере
3. Создать чат по номеру, убедиться в корректности CheckAccount; отправить уникальное короткое сообщение
4. Убедиться на телефоне получателя, что оно пришло; ответить и увидеть ответ в клиенте
5. Проверить статусы и текст со ссылкой/emoji/новой строкой
6. Временно отключить сеть, восстановить её, убедиться в возврате получения без повторной отправки текста
7. Отключить клиент во время ожидания. Подключить другой тестовый инстанс и проверить отсутствие старых чатов/сообщений
8. Снять при желании скриншоты или короткое видео без ключей, DevTools с URL и частных переписок

Не повторяйте отправку автоматически после таймаута: она могла пройти. Не используйте основной рабочий инстанс с ценной очередью уведомлений.
